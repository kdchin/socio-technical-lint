# Replication Package for Rethinking the Socio-Technical Challenges and Outcomes of Linting

[config_mods](./config_mods/) contains overal statistics of which lint rules were changed and how often.

[data](./data/) contains `ineligible.txt` (the projects that were excluded from analysis due to inactivity), `per_sha_metrics.json` (code quality metrics at every commit for every project), and `replication_backup.gz`, which contains all the project data including lint build failures, lint configuration changes, and inline lint configuration changes. See below for instructions and schema.

[statistics_tests](./statistics_tests/) contains the output of regression analysis and ANOVA between the lint features and code metrics.

[survey](./survey/) contains the survey questions asked and responses for the free text questions.

[examined_diffs.csv](examined_diffs.csv) has the commit hashes and consensus labels for the commits we manually assessed for lint violation resolution.

[lint-rules.csv](lint_rules.csv) contains a full list of the 24 lint rules we enabled.

[project_deliverables_spec.tex](project_deliverables_spect.tex) contains a brief description of the specification for each deliverable of the project.


## Loading up `replication_backup.gz`

```bash
mongorestore --uri="YOUR_MONGO_URI" --archive=replication_backup.gz --gzip
```

### Database: `replication`

#### 1. Collection: `projects`
*Houses the primary metadata and summary indicators for each individual team.*

| Field | Type | Description |
| :--- | :--- | :--- |
| `_id` | **Long (Int64)** | Cleaned team identity token (hashed combination of `term` + `team`). |
| `opted_in` | **Boolean** | Indicates whether the team opted into the tracking system features. |
| `total_commits` | **Integer** | Total number of commits processed for this team during the term. |
| `term` | **String** | The academic term token mapped out cleanly (e.g., `"t1"` or `"t2"`). |
| `team` | **Long (Int64)** | Matches the primary `_id` field to maintain data tracking consistency. |
| `c1_position` | **Integer \| Null** | Array index position of the `c1` benchmark commit payload, if it exists. |
| `c2_position` | **Integer \| Null** | Array index position of the `c2` benchmark commit payload, if it exists. |

---

#### 2. Collection: `event_lint_config_changes`
*Tracks modifications made to lint rules and ecosystem configs over time.*

| Field | Type | Description |
| :--- | :--- | :--- |
| `_id` | **ObjectId** | Unique identifier automatically generated by MongoDB. |
| `team_id` | **Long (Int64)** | Foreign key link pointing back to `projects._id`. |
| `term` | **String** | Replicated academic term context code (`"t1"` or `"t2"`). |
| `sha` | **String** | The specific commit hash where configuration modifications occurred. |
| `data` | **Document (Object)** | Contains separate sub-objects mapping string packages/rules to status weights: |
| `data.added` | **Document** | Map of newly added rules and values without target prefixes. |
| `data.modified` | **Document** | Map of updated rule weights and changes. |
| `data.removed` | **Document** | Map of dropped rules removed from the codebase. |

---

#### 3. Collection: `event_inline_exceptions`
*Tracks specific ignore assertions and inline ESLint exception additions.*

| Field | Type | Description |
| :--- | :--- | :--- |
| `_id` | **ObjectId** | Unique identifier automatically generated by MongoDB. |
| `team_id` | **Long (Int64)** | Foreign key link pointing back to `projects._id`. |
| `term` | **String** | Replicated academic term context code (`"t1"` or `"t2"`). |
| `sha` | **String** | The specific commit hash where an exception statement was introduced. |
| `data` | **Document (Object)** | Nested metrics tracking clean exception strings: |
| `data.excepted` | **Document** | Map of newly ignored errors with the package path prefix stripped out. |
| `data.unexcepted` | **Document** | Complementary dictionary tracking dropped ignore states. |

---

#### 4. Collection: `event_inline_unexceptions`
*Tracks the deliberate removal of inline ESLint exception overrides.*

| Field | Type | Description |
| :--- | :--- | :--- |
| `_id` | **ObjectId** | Unique identifier automatically generated by MongoDB. |
| `team_id` | **Long (Int64)** | Foreign key link pointing back to `projects._id`. |
| `term` | **String** | Replicated academic term context code (`"t1"` or `"t2"`). |
| `sha` | **String** | The specific commit hash where exception bypass flags were pulled. |
| `data` | **Document (Object)** | Formatted exactly matching the layout schema of `event_inline_exceptions`. |

---

#### 5. Collection: `event_fail_lint_positions`
*Flattens and tracks every individual linting validation issue or static analysis failure block.*

| Field | Type | Description |
| :--- | :--- | :--- |
| `_id` | **ObjectId** | Unique identifier automatically generated by MongoDB. |
| `team_id` | **Long (Int64)** | Foreign key link pointing back to `projects._id`. |
| `term` | **String** | Replicated academic term context code (`"t1"` or `"t2"`). |
| `ruleId` | **String** | Name of the tripped rule with the package namespace safely stripped out. |
| `severity` | **Integer** | Severity rating level indicator configured in the project (typically `2` for errors). |
| `message` | **String** | The descriptive string logging the root cause detail text of the failure. |
| `line` | **Integer** | The source code file line index position where the alert was triggered. |
| `column` | **Integer** | The column index coordinate tracking the location layout of the problem string. |
